**********************************************************************************************************
Creating a Grafana account and credentials
**********************************************************************************************************

### Phase 1: Establish the Grafana Account

1. Go to **[grafana.com](https://grafana.com/)** and click the **Create Free Account** button in the top right.
2. Sign up using your email or link it directly to your GitHub account.
3. Grafana will ask you to create a **Stack**. A "Stack" is simply your hosted workspace.

- **Stack Name:** Name it something recognizable, `ritual-roast-dev`.
- **Region:** Select a region as close to your AWS deployment as possible.
  If your AWS infrastructure is in `eu-west-2` (London), select the EU/London option if available,
  or Frankfurt/Ireland as a fallback. This minimizes metric latency.

4. Click **Create Stack**. It will take about 60 seconds for Grafana to spin up your cloud environment.

### Phase 2: Generate the Cloud Access Policy Token

Once your stack is ready, you will be in the **Grafana Cloud Portal**
(this is the account management page, not the actual graph dashboard which we ultimately intend to create).

1. On the left-hand sidebar of the Cloud Portal, click on **Access Policies** (it is usually under the _Security_ or _Access Management_ section).
2. Click the **Create Access Policy** button.
3. **Name:** Enter `rr-k3s-alloy-agent`.
4. **Realms:** Select your specific stack (`ritual-roast-dev`) from the dropdown. This ensures the token only has access to this workspace.
5. **Scopes:** This is the most critical part. Your K3s agent only needs to _push_ data, not read it. Check the boxes for:
   - `metrics:write`
   - `logs:write`
   - `traces:write`

6. Click **Create**.
7. On the next screen, click **Add Token**.
8. Give the token a name (e.g., `dev-cluster-token`), set an expiration date
   (or set it to "No Expiration" for this dev environment so it doesn't break on you next month), and click **Create Token**.
9. **Copy the Token Immediately.** It will usually start with the prefix `glc_...`. Once you close this window,
   Grafana will never show you the full token again. So keep a copy handy as you will need it if you want to redeploy this infrastructure again.

### Phase 3: Injecting the Token into Terraform.

Now that you have the token copied to your clipboard, you can inject it into Terraform using environment variables.
Right before you run `terraform plan`, paste it into your active terminal session. Note, you need it again for `terraform destroy`:

`export TF_VAR_grafana_token="glc_YOUR_COPIED_GRAFANA_TOKEN_HERE"`

### Phase 4: Retrieve the Remote Write Endpoint and Instance ID

1. In your Grafana account homepage (`https://grafana.com/orgs/your_org_unique_name`)
   under "Manage your Grafana Cloud stack" click on details
2. In the next window, **"Manage Stack: your_org_unique_name"**, find the "Prometheus" metrics service
3. Click details
4. Scroll down till you reach "Remote Write Endpoint", Copy this value and export it to Terraform variable
   `export TF_VAR_grafana_remote_write_url="https://prometheus-..."`
5. Scroll down a little further to "Username / Instance ID" copy this value and export it to Terraform variable
   `export TF_VAR_grafana_instance_id="123...."`

Note, all the exporting to TF_VARs will be done with the README.md instructions, so you don't need to do it here.
Here just keep the credentials handy and safe.

### Phase 5: Viewing observability with Grafana:

This section will be used right at the end when the cluster is up.

1. On your stacks page `https://grafana.com/orgs/your_org_unique_name`, you should see `Grafana Cloud Portal`. Below it, you'll see `Manage your Grafana Cloud stack`. Click `Launch` and this will bring up your grafana cloud page.
2. On the left panel click on `Dashboards`
Note, the dashboard is not created by Terraform. It must be pushed to your stack once with
`infrastructure/05-aws-k8s/k8s-manifests/observability/dashboards/push-to-grafana.sh` (see the `README.md` in that folder).
The script needs a Grafana instance Service Account token with the Editor role or higher. This is NOT the `glc_...`
token from Phase 2: that token can only write metrics and cannot create dashboards.

3. On the next page you should see, beneath `Dashboards`, `Ritual Roast - v1/v2 Mesh Traffic (Istio)`, click on that and it will display the live metrics of the cluster. This will be useful when you're running canary deployments.
